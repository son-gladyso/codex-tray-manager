# Codex Tray Manager

[简体中文](README.md) · [English](docs/i18n/README.en.md) · [日本語](docs/i18n/README.ja.md) · [한국어](docs/i18n/README.ko.md) · [Español](docs/i18n/README.es.md) · [Français](docs/i18n/README.fr.md) · [Deutsch](docs/i18n/README.de.md) · [Português (Brasil)](docs/i18n/README.pt-BR.md)

**多个 Codex 实例，一个托盘入口。找到窗口、看清后台，再决定如何关闭。**

面向已经在 Windows 上使用隔离启动脚本的用户，Codex Tray Manager 把启动、切换、重启和关闭集中起来，减少在任务栏、脚本和任务管理器之间来回寻找。它管理现有实例，不负责创建账号、迁移聊天或替你搭建隔离环境。

> This is an unofficial community tool and is not affiliated with or endorsed by OpenAI.

需要 Windows 10/11、PowerShell 7，以及一个或多个能够启动隔离 Codex 实例的 PowerShell 脚本。管理器通过每个实例唯一的 `--user-data-dir` 参数识别进程归属。

## 它解决什么问题

当一台 Windows 电脑同时运行多个隔离的 Codex 桌面实例时，用户通常需要在任务栏、任务管理器和多个启动脚本之间来回切换。窗口隐藏后不易找到，普通关闭可能只关掉窗口却留下后台进程，而直接结束整个进程树又可能误杀正在等待应用退出的更新脚本、终端或其他任务。

Codex Tray Manager 提供一个统一的托盘入口，并把“这是应用自己的后台进程”与“这是用途尚未确认的子任务”分开处理。它主要解决：

- 多个 Codex 实例缺少统一的运行状态与操作入口。
- 隐藏窗口或无窗口后台进程难以定位和切回前台。
- 正常退出后 Electron、app-server 等后台进程可能继续残留。
- 粗暴结束进程树可能中断更新脚本、终端或正在执行的工作。
- 多版本实例重启时，难以恢复此前实际运行的版本组合。

## 功能概览

- 根据 JSON 配置动态生成实例菜单，并把运行中的实例自动置顶。
- 启动实例后验证主进程是否稳定运行，避免只根据启动脚本返回值误报成功。
- 枚举隐藏的 Electron 顶层窗口，尝试恢复并切换到前台，同时核验切换结果。
- 关闭时先请求窗口正常退出，再逐一核验并清理确认属于应用的残留进程。
- 使用 PID 与创建时间绑定进程身份，降低 PID 重用导致误操作的风险。
- 发现用途不明的子任务时拦截普通关闭，并显示名称、PID 与创建时间供检查。
- 提供带二次确认的应急关闭，以及逐实例汇总结果的批量关闭。
- 支持 `Standard` 和 `UICanary` 版本，并在重启时恢复之前运行的版本。
- 在后台线程中刷新状态和执行关闭等待，保持托盘菜单响应。
- 写入自动轮换的 JSONL 诊断日志，不记录完整进程命令行或登录凭据。

## 先看一个典型使用流程

1. 先配置至少一个隔离实例；配置多个实例时，确认每个实例使用不同的用户数据目录。
2. 从托盘查看哪些实例正在运行，再把需要的窗口切回前台。
3. 需要退出时先查看进程与关闭检查，分清应用后台和用途未确认的子任务。
4. 使用普通关闭；如果检查发现未确认的任务，先核对原因，不用应急关闭绕过它。
5. 查看最近操作结果，确认实际完成了什么。

本页暂未附托盘菜单的实机截图或录像。以上是操作顺序说明，不是已经录制的演示，也不代表所有启动脚本和 Windows 环境都经过验证。

## 快速开始

先准备三个条件：

- Windows 10/11 与 PowerShell 7（`pwsh`），而不是只安装旧版 Windows PowerShell。
- 能独立启动目标 Codex 的现有 PowerShell 脚本。
- 每个版本对应的绝对启动脚本路径与唯一用户数据目录；示例中的 `D:\codex4` 等路径不能直接照抄。

如果启动脚本本身还不能正常启动，先解决脚本问题，再接入托盘管理器。

普通用户可以从 [Releases](https://github.com/son-gladyso/codex-tray-manager/releases) 下载 Windows 便携版 ZIP，解压后将 `manager.settings.example.json` 复制为 `manager.settings.json` 并填写本机路径。

开发者也可以克隆仓库：

```powershell
git clone https://github.com/son-gladyso/codex-tray-manager.git
cd codex-tray-manager
Copy-Item manager.settings.example.json manager.settings.json
notepad manager.settings.json
pwsh -NoProfile -File .\CodexTrayManager.ps1 -ValidateOnly
```

验证通过后双击 `Start Codex Tray Manager.cmd`。退出管理器不会关闭 Codex。

**第一次成功的标准：**托盘菜单显示你配置的实例，状态刷新后能区分运行与未运行；对一个已运行、可见的测试实例尝试“切换到前台”，再核对操作结果。配置验证通过不代表窗口切换或关闭行为已完成实机验收。先熟悉检查与结果提示，再尝试关闭操作。

## 日常操作

- 统一管理配置中的 Codex 实例（编号范围 4–25），运行中的实例置顶。
- 同一实例可合并管理普通版和 UI 试点版。关闭处理两版；重启恢复之前运行的版本；都未运行时默认启动普通版。
- “启动 / 切换到前台”：启动后验证主进程；已有窗口时尝试恢复并核验前台状态。后台存在但没有窗口时会如实提示。
- “关闭（含应用后台）”：先请求窗口正常退出，最多等待 3 秒，再逐个结束经过身份核验的残留应用进程。
- “查看进程与关闭检查”：查看应用进程和待检查子任务的名称、PID、创建时间。
- “应急关闭（中断全部子任务）”：二次确认后结束所有已发现、可核验身份的子任务，包括更新脚本。只在明确要中断这些任务时使用。
- “关闭所有 Codex”：逐实例汇总结果；失败不影响后续实例处理。完整详情可从“查看最近操作结果”查看。

## 更新脚本与其他子任务

普通关闭和重启遇到无法确认用途的子任务时，会在发送关闭请求之前拦截并列出 PID。
更新脚本、终端、MCP 服务等不能仅凭父子关系都当作应用后台。当前确认的后台包括
同一应用目录的 Electron 进程、直接由 Electron 启动的 app-server，以及同目录的 code-mode host。
其余进程需要检查，不能根据名称包含 update 或 powershell 就推断用途。

**本版没有实现独立更新执行器或自动接管接口。** 拦截不等于接管，也不保证脚本一定能在
应用退出后继续执行。已脱离实例进程树的更新脚本无法由管理器自动识别；这类更新未完成前不要点重启。
请先核对具体脚本与执行方式，避免新旧脚本同时更新。应急关闭明确会中断仍在实例树内的任务。

## 更快的刷新与更稳妥的关闭

- Windows 原生快照获取进程关系和创建时间；只有发现新的应用身份时才查询启动参数。
- 参数缓存以 PID + 创建时间为键，进程退出即清理；父 PID 重用不会继承旧归属。
- 建立共享的进程、父子和用户目录索引；常规状态刷新不枚举窗口。
- 窗口查询、进程刷新、关闭等待和启动验证在独立工作线程执行；界面不再同步等待。
- 默认菜单关闭时每 10 秒刷新，菜单打开时每 2 秒刷新；打开菜单、点击刷新及操作完成后及时刷新。
- 关闭时保留已核验进程的句柄，追踪主进程退出后出现的孤立后台；最后检查全部已知目标。
- 不再调用 `taskkill /T`。每次强制结束均在同一个进程句柄上核验创建时间并执行终止。
- 操作期间禁用重复操作；权限错误、未完成关闭、启动超时和前台切换失败均有反馈。
- 单个启动脚本缺失不会阻止整个托盘启动。缺失的版本仍会在被启动时给出具体错误。

进程快照有时间边界；管理器启动前已经孤立且没有配置标记的后台，不能自动证明归属。
已观察的归属保留在当前管理器会话中，不跨管理器重启推断。Windows 也可能限制抢占前台，
因此切换失败会提示而非宣称成功。

## 配置与诊断

复制 `manager.settings.example.json` 为 `manager.settings.json`，再填写实例目录、各版本启动脚本/用户数据目录、图标及刷新和启动超时。默认本机配置路径已被 Git 忽略；提交前仍需检查暂存区，避免已跟踪、强制添加或另存的私人配置被公开。至少配置一个实例；修改后重新启动管理器生效。配置会检查编号、版本、绝对路径和目录重复。
启动脚本、应用归档、登录、Codex 配置与工作区均不由管理器修改。

“打开诊断日志”进入 `logs`。`manager.jsonl` 保存操作结果、错误和耗时，超过 2 MB 滚动为
`manager.previous.jsonl`。日志不记录完整进程命令行或登录凭据。
配置/依赖导致的启动失败记录在 `startup-error.log`，并显示错误提示。

## 常见问题

**它能替我创建隔离实例或切换账号吗？** 不能。需要先准备自己的启动脚本和独立用户数据目录；管理器不修改登录、Codex 配置或工作区。

**关闭管理器会把工作实例一起关掉吗？** 不会。退出托盘管理器与关闭 Codex 实例是不同操作。

**为什么普通关闭被拦截？** 发现了用途未确认的子任务。先查看名称、PID 和创建时间，确认是否是更新、终端或其他工作；不要为了消除提示而直接使用应急关闭。

**菜单显示后台在运行，为什么找不到窗口？** 实例可能只剩无窗口后台，或 Windows 限制了前台切换。查看操作结果，不能把进程存在等同于窗口可用。

**改了配置为什么还没生效？** 修改本机 `manager.settings.json` 后需重新启动管理器。先用 `-ValidateOnly` 检查编号、版本和路径。

**更新脚本能自动交给管理器接着执行吗？** 不能。当前没有独立更新执行器或接管接口。详见[更新脚本与其他子任务](#更新脚本与其他子任务)。

pwsh -NoProfile -File .\tests\Test-CodexTrayManager.ps1

pwsh -NoProfile -STA -File .\tests\Test-CodexTrayManager.ps1 -Integration

## 缓存加固

缓存淘汰提前到身份查询之前，避免查询部分成功后抛错时跳过清理。每轮复用后台线程前清空
错误、警告等诊断流。主日志保留当前文件和一份轮换文件；启动错误日志超过 256 KB 后也轮换，
只保留一份上一文件。日志阈值允许最后一条记录带来小幅超出。

连续 1000 次部分失败与进程身份变化的回归场景中，旧逻辑积累 1000 条，新逻辑最多 1 条当前记录，
全部退出后为 0。

## 安全边界

普通关闭遇到无法确认用途的子任务时会拦截。菜单中的“应急关闭”会在二次确认后中断该实例树内所有已发现的任务，应仅在明确需要中断更新、终端或其他工作时使用。

## 一起改进

欢迎提交范围明确的文档修正、问题复现和回归测试。不熟悉整个项目也可以从一个具体场景开始：

- 改善配置错误、启动超时或切换失败的提示。
- 给 PID 重用、隐藏窗口、未知子任务等场景补充回归测试。
- 核对不同 Windows 环境下的操作结果，并写清版本与复现步骤。
- 让快速开始和诊断步骤更容易跟随。

先阅读“验证”和“安全边界”。涉及进程归属或关闭逻辑时，优先使用模拟与临时进程测试，不默认操作日常工作实例。提交 PR 时说明问题、改动、实际运行的检查和仍未验证的情况；较大行为改动请先在 [Issues](https://github.com/son-gladyso/codex-tray-manager/issues) 讨论。

请不要提交真实配置、账号资料、完整命令行或含私人路径的诊断截图。贡献不应通过放宽身份核验、跳过确认或强行终止未知任务来“修复”失败。
