# Codex Tray Manager

[简体中文](../../README.md) · [English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md) · [Español](README.es.md) · [Français](README.fr.md) · [Deutsch](README.de.md) · [Português (Brasil)](README.pt-BR.md) · [Русский](README.ru.md) · [繁體中文](README.zh-TW.md)

**多個 Codex 執行個體，一個系統匣入口。找到視窗、看清背景，再決定如何關閉。**

面向已經在 Windows 上使用隔離啟動指令碼的使用者，Codex Tray Manager 把啟動、切換、重啟和關閉集中起來，減少在工作列、指令碼和工作管理員之間來回尋找。它管理現有執行個體，不負責建立帳號、遷移聊天或替你搭建隔離環境。

> 這是非官方社群工具，與 OpenAI 無隸屬關係，也未獲 OpenAI 背書。

需要 Windows 10/11、PowerShell 7，以及一個或多個能夠啟動隔離 Codex 執行個體的 PowerShell 指令碼。管理器透過每個執行個體唯一的 `--user-data-dir` 參數識別處理程序歸屬。

<a id="它解决什么问题"></a>

## 它解決什麼問題

當一臺 Windows 電腦同時執行多個隔離的 Codex 桌面執行個體時，使用者通常需要在工作列、工作管理員和多個啟動指令碼之間來回切換。視窗隱藏後不易找到，普通關閉可能只關掉視窗卻留下背景處理程序，而直接結束整個處理程序樹又可能誤殺正在等待應用退出的更新指令碼、終端或其他任務。

Codex Tray Manager 提供一個統一的系統匣入口，並把“這是應用程式自己的背景處理程序”與“這是用途尚未確認的子任務”分開處理。它主要解決：

- 多個 Codex 執行個體缺少統一的執行狀態與操作入口。
- 隱藏視窗或無視窗背景處理程序難以定位和切回前景。
- 正常退出後 Electron、app-server 等背景處理程序可能繼續殘留。
- 粗暴結束處理程序樹可能中斷更新指令碼、終端或正在執行的工作。
- 多版本執行個體重啟時，難以恢復此前實際執行的版本組合。

<a id="功能概览"></a>

## 功能概覽

- 根據 JSON 設定動態生成執行個體選單，並把執行中的執行個體自動置頂。
- 啟動執行個體後驗證主處理程序是否穩定執行，避免只根據啟動指令碼返回值誤報成功。
- 列舉隱藏的 Electron 頂層視窗，嘗試恢復並切換到前景，同時核驗切換結果。
- 關閉時先請求視窗正常退出，再逐一核驗並清理確認屬於應用的殘留處理程序。
- 使用 PID 與建立時間繫結處理程序身分，降低 PID 重用導致誤操作的風險。
- 發現用途不明的子任務時攔截普通關閉，並顯示名稱、PID 與建立時間供檢查。
- 提供帶二次確認的應急關閉，以及逐執行個體彙總結果的批次關閉。
- 支援 `Standard` 和 `UICanary` 版本，並在重啟時恢復之前執行的版本。
- 在背景執行緒中重新整理狀態和執行關閉等待，保持系統匣選單回應。
- 寫入自動輪換的 JSONL 診斷記錄，不記錄完整處理程序命令列或登入憑據。

<a id="先看一个典型使用流程"></a>

## 先看一個典型使用流程

1. 先設定至少一個隔離執行個體；設定多個執行個體時，確認每個執行個體使用不同的使用者資料目錄。
2. 從系統匣檢視哪些執行個體正在執行，再把需要的視窗切回前景。
3. 需要退出時先檢視程序與關閉檢查，分清應用背景和用途未確認的子任務。
4. 使用普通關閉；如果檢查發現未確認的任務，先核對原因，不用應急關閉繞過它。
5. 檢視最近操作結果，確認實際完成了什麼。

本頁暫未附系統匣選單的實機截圖或錄影。以上是操作順序說明，不是已經錄製的示範，也不代表所有啟動指令碼和 Windows 環境都經過驗證。

<a id="快速开始"></a>

## 快速開始

先準備三個條件：

- Windows 10/11 與 PowerShell 7（`pwsh`），而不是只安裝舊版 Windows PowerShell。
- 能獨立啟動目標 Codex 的現有 PowerShell 指令碼。
- 每個版本對應的絕對啟動指令碼路徑與唯一使用者資料目錄；示例中的 `D:\codex4` 等路徑不能直接照抄。

如果啟動指令碼本身還不能正常啟動，先解決指令碼問題，再接入系統匣管理器。

普通使用者可以從 [Releases](https://github.com/son-gladyso/codex-tray-manager/releases) 下載 Windows 可攜版 ZIP，解壓後將 `manager.settings.example.json` 複製為 `manager.settings.json` 並填寫本機路徑。

開發者也可以複製儲存庫：

```powershell
git clone https://github.com/son-gladyso/codex-tray-manager.git
cd codex-tray-manager
Copy-Item manager.settings.example.json manager.settings.json
notepad manager.settings.json
pwsh -NoProfile -File .\CodexTrayManager.ps1 -ValidateOnly
```

驗證透過後雙擊 `Start Codex Tray Manager.cmd`。退出管理器不會關閉 Codex。

**第一次成功的標準：**系統匣選單顯示你設定的執行個體，狀態重新整理後能區分執行與未執行；對一個已執行、可見的測試執行個體嘗試“切換到前景”，再核對操作結果。設定驗證透過不代表視窗切換或關閉行為已完成實機驗收。先熟悉檢查與結果提示，再嘗試關閉操作。

<a id="日常操作"></a>

## 日常操作

- 統一管理設定中的 Codex 執行個體（編號範圍 4–25），執行中的執行個體置頂。
- 同一執行個體可合併管理普通版和 UI 試點版。關閉處理兩版；重啟恢復之前執行的版本；都未執行時預設啟動普通版。
- “啟動 / 切換到前景”：啟動後驗證主處理程序；已有視窗時嘗試恢復並核驗前景狀態。背景存在但沒有視窗時會如實提示。
- “關閉（含應用背景）”：先請求視窗正常退出，最多等待 3 秒，再逐個結束經過身分核驗的殘留的應用程式處理程序。
- “檢視程序與關閉檢查”：檢視應用程式處理程序與待檢查子任務的名稱、PID、建立時間。
- “應急關閉（中斷全部子任務）”：二次確認後結束所有已發現、可核驗身分的子任務，包括更新指令碼。只在明確要中斷這些任務時使用。
- “關閉所有 Codex”：逐執行個體彙總結果；失敗不影響後續執行個體處理。完整詳情可從“檢視最近操作結果”檢視。

<a id="更新脚本与其他子任务"></a>

## 更新指令碼與其他子任務

普通關閉和重啟遇到無法確認用途的子任務時，會在傳送關閉請求之前攔截並列出 PID。
更新指令碼、終端、MCP 服務等不能僅憑父子關係都當作應用背景。當前確認的背景包括
同一應用目錄的 Electron 程序、直接由 Electron 啟動的 app-server，以及同目錄的 code-mode host。
其餘程序需要檢查，不能根據名稱包含 update 或 powershell 就推斷用途。

**本版沒有實現獨立更新執行器或自動接管介面。** 攔截不等於接管，也不保證指令碼一定能在
應用退出後繼續執行。已脫離執行個體處理程序樹的更新指令碼無法由管理器自動識別；這類更新未完成前不要點重啟。
請先核對具體指令碼與執行方式，避免新舊指令碼同時更新。應急關閉明確會中斷仍在執行個體樹內的任務。

<a id="更快的刷新与更稳妥的关闭"></a>

## 更快的重新整理與更穩妥的關閉

- Windows 原生快照獲取程序關係和建立時間；只有發現新的應用身分時才查詢啟動參數。
- 參數快取以 PID + 建立時間為鍵，程序退出即清理；父 PID 重用不會繼承舊歸屬。
- 建立共享的程序、父子和使用者目錄索引；常規狀態重新整理不列舉視窗。
- 視窗查詢、程序重新整理、關閉等待和啟動驗證在獨立工作執行緒執行；介面不再同步等待。
- 預設選單關閉時每 10 秒重新整理，選單開啟時每 2 秒重新整理；開啟選單、點選重新整理及操作完成後及時重新整理。
- 關閉時保留已核驗程序的控制代碼，追蹤主處理程序退出後出現的孤立背景；最後檢查全部已知目標。
- 不再呼叫 `taskkill /T`。每次強制結束均在同一個程序控制代碼上核驗建立時間並執行終止。
- 操作期間禁用重複操作；許可權錯誤、未完成關閉、啟動超時和前景切換失敗均有回饋。
- 單個啟動指令碼缺失不會阻止整個系統匣啟動。缺失的版本仍會在被啟動時給出具體錯誤。

程序快照有時間邊界；管理器啟動前已經孤立且沒有設定標記的背景，不能自動證明歸屬。
已觀察的歸屬保留在當前管理器會話中，不跨管理器重啟推斷。Windows 也可能限制搶佔前景，
因此切換失敗會提示而非宣稱成功。

<a id="配置与诊断"></a>

## 設定與診斷

複製 `manager.settings.example.json` 為 `manager.settings.json`，再填寫執行個體目錄、各版本啟動指令碼/使用者資料目錄、圖示及重新整理和啟動超時。預設本機設定路徑已被 Git 忽略；提交前仍需檢查暫存區，避免已跟蹤、強制新增或另存的私人設定被公開。至少設定一個執行個體；修改後重新啟動管理器生效。設定會檢查編號、版本、絕對路徑和目錄重複。
啟動指令碼、應用歸檔、登入、Codex 設定與工作區均不由管理器修改。

“開啟診斷記錄”進入 `logs`。`manager.jsonl` 儲存操作結果、錯誤和耗時，超過 2 MB 滾動為
`manager.previous.jsonl`。記錄不記錄完整處理程序命令列或登入憑據。
設定/依賴導致的啟動失敗記錄在 `startup-error.log`，並顯示錯誤提示。

<a id="常见问题"></a>

## 常見問題

**它能替我建立隔離執行個體或切換帳號嗎？** 不能。需要先準備自己的啟動指令碼和獨立使用者資料目錄；管理器不修改登入、Codex 設定或工作區。

**關閉管理器會把工作執行個體一起關掉嗎？** 不會。退出系統匣管理器與關閉 Codex 執行個體是不同操作。

**為什麼普通關閉被攔截？** 發現了用途未確認的子任務。先檢視名稱、PID 和建立時間，確認是否是更新、終端或其他工作；不要為了消除提示而直接使用應急關閉。

**選單顯示背景在執行，為什麼找不到視窗？** 執行個體可能只剩無視窗背景，或 Windows 限制了前景切換。檢視操作結果，不能把程序存在等同於視窗可用。

**改了設定為什麼還沒生效？** 修改本機 `manager.settings.json` 後需重新啟動管理器。先用 `-ValidateOnly` 檢查編號、版本和路徑。

**更新指令碼能自動交給管理器接著執行嗎？** 不能。當前沒有獨立更新執行器或接管介面。詳見[更新指令碼與其他子任務](#更新脚本与其他子任务)。

<a id="缓存加固"></a>

## 快取加固

快取淘汰提前到身分查詢之前，避免查詢部分成功後拋錯時跳過清理。每輪重複使用背景執行緒前清空
錯誤、警告等診斷流。主記錄保留當前檔案和一份輪換檔案；啟動錯誤記錄超過 256 KB 後也輪換，
只保留一份上一檔案。記錄閾值允許最後一條記錄帶來小幅超出。

連續 1000 次部分失敗與處理程序身分變化的迴歸場景中，舊邏輯積累 1000 條，新邏輯最多 1 條當前記錄，
全部退出後為 0。

<a id="安全边界"></a>

## 安全邊界

普通關閉遇到無法確認用途的子任務時會攔截。選單中的“應急關閉”會在二次確認後中斷該執行個體樹內所有已發現的任務，應僅在明確需要中斷更新、終端或其他工作時使用。

<a id="一起改进"></a>

## 一起改進

歡迎提交範圍明確的文件修正、問題復現和迴歸測試。不熟悉整個專案也可以從一個具體場景開始：

- 改善設定錯誤、啟動超時或切換失敗的提示。
- 給 PID 重用、隱藏視窗、未知子任務等場景補充迴歸測試。
- 核對不同 Windows 環境下的操作結果，並寫清版本與復現步驟。
- 讓快速開始和診斷步驟更容易跟隨。

先閱讀“驗證”和“安全邊界”。涉及處理程序歸屬或關閉邏輯時，優先使用模擬與臨時程序測試，不預設操作日常工作執行個體。提交 PR 時說明問題、改動、實際執行的檢查和仍未驗證的情況；較大行為改動請先在 [Issues](https://github.com/son-gladyso/codex-tray-manager/issues) 討論。

請不要提交真實設定、帳號資料、完整命令列或含私人路徑的診斷截圖。貢獻不應透過放寬身分核驗、跳過確認或強行終止未知任務來“修復”失敗。
